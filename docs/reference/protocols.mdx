# Network Protocols

This document analyzes the network protocols and communication systems used by the Nest Learning Thermostat.

## Overview

The Nest thermostat implements multiple network protocols:

1. **Weave** - Google's IoT application protocol
2. **Thread** - IEEE 802.15.4-based mesh networking
3. **Wi-Fi** - Primary internet connectivity (802.11 b/g/n)
4. **ZigBee** - Legacy mesh networking support
5. **TCP/IP** - Standard internet protocols

## Weave Protocol

### Architecture

Weave is Google's application-layer protocol for IoT devices, providing:
- Secure device-to-device communication
- Device-to-cloud communication
- Service discovery
- Data management
- Software updates
- Network provisioning

**Library**: `/nestlabs/lib/libnlweavetools.a` (334 KB)

### Weave Security

#### Pairing Process

**Environment Variables**:
- `kWeavePrivateKey` - Device private key
- `kWeavePairingCode` - Pairing code for setup
- `kWeaveCertificate` - Device certificate

**Pairing Flow**:
1. User initiates pairing in Nest app
2. Device broadcasts pairing availability
3. App discovers device
4. User enters pairing code
5. CASE session established
6. Device provisioned with network credentials
7. Device registers with Nest cloud

#### Certificate Authentication

The system uses X.509 certificates for authentication:
- Device certificates signed by Nest CA
- Certificate chain validation
- ASN.1 parsing (`nl::Weave::ASN1`)
- OID (Object Identifier) table

#### Session Management

- **Secure Sessions**: Encrypted with session keys
- **Unsecured Connections**: For initial pairing only
- **Session Timeout**: Automatic session expiration
- **Session Callbacks**: Connection state notifications

### Weave Bindings

- Connection establishment

### TLV (Tag-Length-Value) Encoding

Efficient binary serialization:

### Network Integration

Weave integrates with lower-level protocols:
- **TCP/IP**: Primary transport via `nl::Inet::TCPEndPoint`
- **UDP**: For discovery and lightweight messages
- **Thread**: For mesh networking
- **Wi-Fi**: For internet connectivity

## Thread / WPAN

### wpantund - WPAN Tunnel Daemon

**Binary**: `/usr/sbin/wpantund`  
**Control**: `/usr/bin/wpanctl`  
**Config**: `/etc/wpantund.conf`

wpantund provides a tunnel interface for Thread/ZigBee networking.

### Configuration

**Interface**: `wpan0` (virtual network interface)

**NCP (Network Co-Processor)**: EM357 chip via SPI

**SPI Configuration**:
```
Device: /dev/spidev2.0
Interrupt: /sys/devices/platform/diamond-zigbee/interrupt/value
Reset: /sys/devices/platform/diamond-zigbee/reset#/value
Wake: /sys/devices/platform/diamond-zigbee/wake/value
```

**Radio Parameters**:
- **TX Power**: -15 dBm (default)
- **TX Power Limit**: -10 dBm (to protect Wi-Fi FEM)
- **TX Power Mode**: 5 (boost mode, external PA)
- **CCA Threshold**: -70 dBm (configurable)

### Thread Features

Thread provides:
- **IPv6 Mesh Network**: Self-healing mesh topology
- **Low Power**: Sleepy end device support
- **Secure**: Built-in encryption
- **Reliable**: Automatic routing and recovery

**Device Modes**:
```cpp
nl::WPANCtl::Interface::SetThreadDeviceMode
```

Possible modes:
- Router
- End Device
- Sleepy End Device
- Commissioner

### Firmware Management

**Firmware Check**:
```bash
/nestlabs/bin/zb-loader --is-update-required /usr/share/silabs/data/firmware/ip-modem-app.bin
```

**Firmware Update**:
```bash
/nestlabs/bin/zb-loader --app-easyload /usr/share/silabs/data/firmware/ip-modem-app.bin
```

**Auto-Update**: Enabled by default

### Legacy Support

The configuration enables legacy mode for backward compatibility:
```
com.nestlabs.internal:Legacy:Enabled true
com.nestlabs.internal:Legacy:PreferInterface true
```

This suggests support for older Nest devices or protocols.

## Network Provisioning

### Initial Setup

1. **Access Point Mode**: Device creates temporary Wi-Fi AP
2. **Mobile App Connection**: User connects phone to device AP
3. **Credential Transfer**: App sends Wi-Fi credentials via Weave
4. **Network Connection**: Device connects to home Wi-Fi
5. **Cloud Registration**: Device registers with Nest cloud

## Security Considerations

### Attack Surface

**Network Services**:
- SSH (port 22) - May be disabled in production
- mDNS (port 5353) - Local network only
- Weave - Encrypted with certificates

**Potential Vulnerabilities**:
- Wi-Fi credential storage
- Certificate private key storage
- Weave protocol implementation
- Thread mesh security
- Cloud API authentication

### Encryption

- **Wi-Fi**: WPA2 encryption
- **Weave**: TLS-like encryption with CASE
- **Thread**: AES-128 encryption
- **HTTPS**: TLS 1.2+ to cloud

### Certificate Storage

Certificates and keys stored in:
- `/media/system-config/` (SSH keys)
- Weave environment variables
- Secure storage (implementation unclear)
