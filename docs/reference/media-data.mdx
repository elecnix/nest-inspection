# Data Partition (/media/data)

**Device**: mtdblock12  
**Size**: 20MB  
**Usage**: 6% (1.2MB used)  
**Mount**: Read-write JFFS2  
**Purpose**: Thermostat operational data and state

## Overview

The data partition contains 29 files storing critical thermostat operational state, learning data, and runtime information. Files use two formats:

- **`.recovery`** - Binary format with checksums for critical state
- **`.json`** - Human-readable JSON for configuration

## Schedule Management

### schedulemanager.recovery
**Format**: Binary recovery  
**Size**: ~50KB  
**Purpose**: Current schedule state and active schedule slots

**Contains**:
- Active schedule entries
- Current schedule slot
- Next scheduled transition
- Schedule learning state
- User modifications

**Updated**: On schedule changes, transitions, and learning events

**Critical**: Yes - Loss causes schedule reset

### schedulescore.HEAT.recovery
**Format**: Binary recovery  
**Size**: ~20KB  
**Purpose**: Heating schedule learning scores

**Contains**:
- Learning scores for each schedule slot
- Historical performance metrics
- Confidence levels
- Optimization data

**Updated**: During learning and schedule execution

### schedulescore.COOL.recovery
**Format**: Binary recovery  
**Size**: ~20KB  
**Purpose**: Cooling schedule learning scores

**Contains**: Same structure as HEAT, for cooling mode

### schedulescore.RANGE.recovery
**Format**: Binary recovery  
**Size**: ~20KB  
**Purpose**: Range mode (heat-cool) schedule learning scores

**Contains**: Same structure as HEAT, for range mode

## Occupancy & Auto-Away

### autoaway.recovery
**Format**: Binary recovery  
**Size**: ~30KB  
**Purpose**: Auto-away detection state and history

**Contains**:
- Current occupancy state (home/away)
- Motion detection history
- Occupancy prediction model
- Auto-away triggers
- Last action and actor (user/auto)
- Learning data

**Updated**: On motion events, state changes, and predictions

**Critical**: Yes - Loss causes auto-away reset

**Key Data**:
- `away_state` - Current state
- `last_action` - Last occupancy action
- `last_action_by` - Source (user/schedule/auto)
- Motion sensor history
- Prediction confidence

## Prediction & Learning

### predictionmanager.json
**Format**: JSON  
**Size**: ~15KB  
**Purpose**: Temperature prediction models (JSON format)

**Contains**:
```json
{
  "predicted_completion_time_utc": "2019-09-12T15:30:00Z",
  "predicted_afterglow_end_time_utc": "2019-09-12T15:45:00Z",
  "predicted_expiration_time_utc": "2019-09-12T16:00:00Z",
  "OnOffModel": {
    "heating": {...},
    "cooling": {...}
  },
  "ModulationModel": {...},
  "AutoTuneModel": {...},
  "AlgoLearnerStates": [...]
}
```

**Key Fields**:
- `predicted_completion_time_utc` - Time to reach setpoint
- `predicted_afterglow_end_time_utc` - System coast time

- `ModulationModel` - Modulating HVAC model

**Updated**: Continuously during operation

## File Characteristics

### Recovery Files (.recovery)

**Format**: Binary with checksums  
**Features**:
- Atomic writes
- Power-loss protection
- Corruption detection
- Automatic recovery

**Structure**:
```
[Header: Magic + Version + Checksum]
[Data: Binary serialized data]
[Footer: Checksum]
```

**Advantages**:
- Survives power loss
- Detects corruption
- Fast read/write

**Disadvantages**:
- Not human-readable
- Requires special tools to inspect

### JSON Files (.json)

**Format**: Human-readable JSON  
**Features**:
- Easy to inspect
- Can be manually edited
- Standard format

**Advantages**:
- Human-readable
- Easy to debug
- Standard tools

**Disadvantages**:
- No power-loss protection
- Larger file size
- Slower parsing

## Data Persistence

### Critical Data (Recovery Files)
**Backup**: Uploaded to cloud periodically  
**Recovery**: Restored from cloud or rebuilt from defaults  
**Loss Impact**: Feature reset, relearning required

### Configuration (JSON Files)
**Backup**: Uploaded to cloud  
**Recovery**: Restored from cloud or defaults  
**Loss Impact**: Reconfiguration required

### Debugging (Crash Files)
**Backup**: Uploaded once  
**Recovery**: Not recovered  
**Loss Impact**: None (diagnostic only)

## Common Operations

### Viewing JSON Files
```bash
cat /media/data/rateplan.json | jq .
cat /media/data/smartthermostatmanager.json | jq .
```

### Listing All Data Files
```bash
ls -lh /media/data/
```

### Checking File Sizes
```bash
du -h /media/data/*
```

### Backing Up Data Partition
```bash
tar czf /media/scratch/data-backup.tar.gz /media/data/
```

### Finding JSON Files
```bash
find /media/data -name "*.json" -exec cat {} \;
```

## Troubleshooting

### Corrupted Recovery Files

**Symptoms**: Feature not working, error logs  
**Cause**: Power loss during write, flash corruption  
**Solution**:
1. System attempts automatic recovery
2. Restored from cloud backup
3. Rebuilt from defaults if necessary

### Missing Data Files

**Symptoms**: Features reset, relearning required  
**Cause**: Partition corruption, failed update  
**Solution**:
1. Check partition integrity
2. Restore from backup
3. Allow system to rebuild

### Large Crash Files

**Symptoms**: Data partition filling up  
**Cause**: Repeated crashes  
**Solution**:
1. Upload crash files to cloud
2. Delete old crash files
3. Investigate crash cause
