# Filesystem Structure

The Nest Learning Thermostat uses a sophisticated multi-partition MTD (Memory Technology Device) flash storage layout.

## Partition Layout

The device uses 6 primary MTD block partitions:

| Partition | Device | Size | Mount Point | Usage | Typical Usage |
|-----------|--------|------|-------------|-------|---------------|
| Root | mtdblock9 | 46MB | / | Root filesystem | 58% |
| System Config | mtdblock10 | 4MB | /media/system-config | System settings | 11% |
| User Config | mtdblock11 | 8MB | /media/user-config | User preferences | 7% |
| Data | mtdblock12 | 20MB | /media/data | Runtime data | 6% |
| Log | mtdblock13 | 20MB | /media/log | System logs | 4% |
| Scratch | mtdblock14 | 92MB | /media/scratch | Temporary storage | 4% |

**Total Storage**: 196MB

## Filesystem Types

- **Root (/)**: Read-only JFFS2 (Journaling Flash File System 2)
- **Media partitions**: JFFS2 with write support
- **Tmpfs**: RAM-based temporary filesystems (/tmp, /var/run, /var/lock)
- **Devtmpfs**: Device file management (/dev)

## Storage Management

### Read-Only Root
The root filesystem is mounted read-only to prevent corruption and enable reliable recovery. All writable data is stored on separate partitions.

### Wear Leveling
JFFS2 provides wear leveling for flash memory, distributing writes evenly across the flash to extend device lifetime.

### Recovery System
Multiple recovery mechanisms protect against corruption:
- Recovery files (.recovery) store critical state
- Backup configurations enable rollback
- Watchdog monitors system health
- Multi-tier recovery system (see Recovery documentation)

## Data Persistence

### Critical State
Stored in `.recovery` files using a binary format designed for reliability and atomic updates.

### Configuration
JSON files store less critical configuration that can be regenerated or reset.

### Logs
Rotated and managed to prevent partition overflow while maintaining debugging capability.

<Info>
  The partition layout provides separation of concerns, enabling safe updates, reliable recovery, and efficient storage management on resource-constrained embedded hardware.
</Info>
